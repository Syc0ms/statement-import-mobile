# Self-review

## Ключевые решения

1. **Платформонезависимое ядро + одна машина состояний.** Вся логика операции (`app/src/core`)
   не зависит от React Native: файловая система, загрузка, хранилище и таймеры — через интерфейсы.
   Поэтому сбои проверяются автотестами против **настоящего** mock из `kit/` (случайный порт,
   временный state), включая relaunch (новый store + controller над тем же хранилищем) и
   «приложение убито во время POST». Счётчики `newJobs`/`duplicateHits`/`deleteRequests`
   проверяются по `/__test/state`, а не по клиенту.
2. **Честность — в коде, а не в вёрстке.** Статусы сервера сливаются только в `reduceJob`
   (строго большая ревизия, `deleted` терминален). Что экран вправе сказать, решает чистая
   `presentOperation` с тестами: 202 → «В очереди», «Удалено с сервера» — только если GET вернул
   `deleted`; тело 202 от DELETE с `deleted` намеренно не принимается как подтверждение.
   Ключ создаётся и сохраняется до POST; переотправка — только по действию пользователя, тем же
   ключом и только если SHA-256 копии совпадает с записанным.
3. **Минимальное хранение файла.** Копия picker'а сразу переносится в свою папку под случайным
   именем, читаются только первые 64 байта, хеш и загрузка — нативно из файла. Копия удаляется,
   как только сервер подтвердил задание (раньше, чем «в конце сценария»): после этого повтор
   отправки уже не нужен. Логгер пропускает только allow-list безопасных полей.

## Что упрощено ради срока

- Одна активная операция; нет очереди импортов и истории.
- Опрос только на переднем плане (AppState), без фоновой загрузки и push.
- Нет миграций схемы записи (есть только поле `schema: 1`).
- Навигация — системные модальные листы вместо роутера; локализация только русская.
- UI-тестов (Detox/Maestro) нет: поведение покрыто тестами ядра и презентации, экран проверен руками.
- Android не запускался — помечен как непроверенный. Работаю на одном Mac (macOS) без Android-устройства;
  Android SDK/эмулятора нет, а свободного места на диске ~8 ГБ при необходимых ~10+ ГБ
  (Android Studio + SDK + образ эмулятора). Код и конфигурация для Android готовы.

## Что сломается первым в production и как заметим

- **Пропавшая копия при неизвестном исходе.** iOS может очистить `Caches`, пока приложение
  выгружено. Сейчас приложение просит выбрать тот же файл и сверяет SHA-256. Заметим по доле
  операций с `copy_missing` в безопасных логах.
- **Долгие загрузки на плохой сети.** Таймаут 60 с превращается в «исход неизвестен», и
  пользователь видит восстановление по ключу. Рост `upload.unknown` и времени до `recovery.found`
  — первый сигнал. Решение — фоновая сессия загрузки (нужен новый бинарник).
- **Сервер без строгих ревизий.** Если бэкенд когда-нибудь отдаст новое состояние с той же
  ревизией, клиент его проигнорирует — UI «зависнет». Заметим по операциям, которые долго стоят
  в `queued/processing` на клиенте при `ready` на сервере.

## Роли: я и AI

**Моё — архитектура, спецификация и приёмка.** До написания кода я разобрал PDF и набор mock,
составил требования (`docs/REQUIREMENTS_CHECKLIST.md`) и подробную техническую спецификацию:

- модель надёжности: запись операции с ключом сохраняется **до** POST, неизвестный исход →
  `GET /by-key`, переотправка только пользователем тем же ключом и теми же байтами (SHA-256);
- единый чистый reducer ревизий; «удалено» — только по GET `deleted`; отдельный ключ удаления;
- граница ядра: платформонезависимое `core` + порты (файлы, загрузка, хранилище, таймер);
- приватность: своя папка-кэш, чтение только заголовка, нативная загрузка, allow-list логгер;
- стратегия тестов: интеграция против **настоящего** mock на случайном порту, relaunch как
  пересоздание store + controller;
- визуальные принципы и состояния экрана, требования к доказательствам (видео + счётчики).
