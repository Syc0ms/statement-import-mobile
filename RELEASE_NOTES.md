# Release notes — импорт выписки (тестовый фрагмент)

## Разрешения

- **Runtime-разрешений нет** ни на iOS, ни на Android. Файл выбирается системным picker'ом
  (iOS `UIDocumentPickerViewController`, Android Storage Access Framework): пользователь сам
  выдаёт доступ к одному файлу, приложение сразу копирует его в свой кэш.
  Нет `READ_EXTERNAL_STORAGE`/`READ_MEDIA_*`, нет доступа к фото, камере, контактам.
- В `Info.plist` есть два ключа, нужных **только тестовой сборке**, которая ходит на mock по HTTP:
  - `NSAppTransportSecurity → NSAllowsLocalNetworking = true` — разрешает HTTP к локальному адресу;
  - `NSLocalNetworkUsageDescription` — iOS покажет запрос «локальная сеть», только если на
    телефоне указать LAN-адрес Mac. В симуляторе (127.0.0.1) запроса нет.
  Продовая сборка ходит в API по HTTPS: оба ключа удаляются.
- Android: debug-сборка разрешает cleartext HTTP (шаблон React Native/Expo для debug).
  В release cleartext выключен; продовый API — только HTTPS.

## Где лежат копии файла и когда удаляются

| Что | iOS | Android |
|---|---|---|
| Копия от picker'а | `Library/Caches/DocumentPicker/` в песочнице приложения | `cacheDir/DocumentPicker/` (внутреннее хранилище приложения) |
| Рабочая копия | `Library/Caches/statement-import/<uuid>.bin` | `cacheDir/statement-import/<uuid>.bin` |

- Копия picker'а сразу переносится (move) в `statement-import/` под случайным именем:
  исходное имя файла на диске не остаётся.
- Копия удаляется: при локальном отказе (не тот формат, больше 10 МиБ); при «Отмена» на экране
  подтверждения; как только сервер подтвердил задание (202 или найдено по ключу) — повторная
  отправка после этого уже не нужна; при отказе сервера (4xx); при «Отказаться от импорта»,
  «Новый импорт», «Очистить данные на устройстве».
- Копия **сохраняется** только пока исход POST неизвестен или по ключу пришёл 404: она нужна
  для повтора с тем же ключом и теми же байтами (SHA-256 сверяется перед повтором).
- При каждом запуске приложение удаляет из обеих папок всё, что не принадлежит активной операции.
- Кэш iOS не попадает в бэкап iCloud; ОС может очистить его при нехватке места. Если копия
  пропала, а исход неизвестен, приложение просит выбрать тот же файл и принимает его, только если
  SHA-256 совпадает.
- В `AsyncStorage` хранится запись операции: ключи (импорта и удаления), фаза, путь к копии,
  размер, формат, SHA-256, имя файла (для `X-File-Name` при повторе) и снимок статуса с сервера.
  Байтов файла там нет.

## Как очистить данные

- В приложении: «Тест-панель → Очистить данные на устройстве» удаляет запись операции и все
  временные копии. На завершённом импорте то же делает «Новый импорт».
- Серверные данные удаляются только кнопкой «Удалить с сервера» и считаются удалёнными только
  после `GET … → deleted`.
- Системно: удалить приложение (iOS) или «Очистить хранилище» в настройках приложения (Android).

## Что остановит rollout

- Рост доли заданий, созданных одним пользователем повторно для одного файла (на бэкенде:
  несколько job на один `sha256` от одного клиента за короткое время) — признак того, что ключ
  не переживает relaunch. Это стоп-фактор.
- Любой случай «на клиенте deleted, на сервере не deleted» (сверка по job id).
- Доля операций, застрявших в «исход неизвестен» / `not_found` дольше N минут, или рост 409
  (один ключ — разные байты) и 415/413 от сервера после локальной проверки.
- Любая находка имени файла, байтов или описаний операций в логах/краш-репортах.
- Рост крашей на экране выбора файла или ошибок чтения копии на какой-либо версии ОС.

Сигналы — по серверным метрикам и безопасному логгеру (только статусы, ревизии, коды ошибок,
суффикс ключа); в этом фрагменте аналитики и crash SDK нет.

## OTA (JS) или новый нативный бинарник

**Можно обновить по OTA (JS-бандл):** логика состояний, reducer ревизий, backoff опроса, тексты,
UI и анимации, правила валидации содержимого, лимит размера, формат записи операции (с миграцией
схемы `schema: 1`), адрес API.

**Нужен новый бинарник:** новые или обновлённые нативные модули (expo-file-system,
expo-document-picker, expo-crypto, AsyncStorage, Reanimated), смена Expo SDK/React Native,
любые изменения `Info.plist`/`AndroidManifest` (ATS, cleartext, разрешения, локальная сеть),
bundle id / package, иконка, переход на фоновую сессию загрузки.
OTA-обновление должно проверять совместимость runtime-версии, иначе JS может вызвать
отсутствующий нативный метод.
